# Source and history

This is a selected adaptation of personal acquisition, adapter and downstream source-verification code, not a copy of an operational repository.

Two neutral acquisition snapshots retain their original author/committer identity, timestamps and messages:

| Retained commit | Original date | Subject |
| --- | --- | --- |
| `3ebcbfd63118f0034c2543f79cf5b9ae8a942845` | July 24, 2026 | Enforce connector-backed collection orchestration |
| `34f5612119a42b6d1336aa27325db721562219d8` | July 26, 2026 | Add runtime transport and landing harness |

These commits were path-filtered to only `collection.py` and `runtime.py`. Their hashes changed because their trees/history changed. Their selected source snapshots are not standalone runnable releases; external registry dependencies were deliberately not imported. The current adaptation replaces those historical paths with the five small modules described in the README.

The current acquisition baseline also contributed its later deterministic variant behavior. Physical-source path/hash verification and the `InvokeResult` envelope were adapted from separate personal components. Their complete commits, logical JSON branches, private app interfaces and operational context are excluded. The original-to-extract commit/blob/function map remains private; no real record corpus or provider inventory was used to generate fixtures.

| Current symbol | Lineage | Adaptation |
| --- | --- | --- |
| `sample.TransportResponse`, `VerifiedArtifact`, `SinkResult`, `collect` | Acquisition typed boundaries and core ordering | Fixed request/route replaces provider registry; added explicit readback evidence and uncertainty propagation |
| `runtime.ArtifactContract`, `SignatureVerifier` | Acquisition runtime verifier | Exact generated bytes and identity equality replace reliance on metadata attestation alone |
| `runtime.FileSystemSink` | Acquisition filesystem sink | Duplicate/full-hash variants retained; directory-relative no-clobber writes, bounded safe reads and final readback are new |
| `source_identity.backing_path`, `_backing_path`, `SourceVerifier.verify` | Downstream source identity verifier | Physical branch only; nonblocking/no-follow regular-file handling added |
| `mock_mcp.InvokeResult.as_tool_payload` | Thin adapter result envelope | Envelope retained; in-process mock and strict consumer added; no real process invocation |
| Test fakes and rejection/tamper scenarios | Acquisition and physical-verifier test patterns | Regenerated identity fixtures; added race, special-file and fault-injection cases |

New implementation commits use their actual dates. No new work is backdated. Preserving selected history does not imply every source line was manually written, nor that the complete private history is safe to publish. AI assistance was used for adaptation and review. Third-party skills, runtimes and source packages are not bundled.
